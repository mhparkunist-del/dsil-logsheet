# DSIL Run Sheet

KAIST Device-to-System Integration Lab (DSIL) 의 **공정 런시트**입니다. 반도체 소자 · 패키징 공정을 **모듈**(재사용 공정 단위) → **흐름**(행 × 분기 런시트 템플릿) → **런**(내가 만든 실행)
으로 체계화하고, 런시트는 **빈 시트에서 라이브러리를 불러와 직접 구성**하거나 흐름을 복사해 시작합니다. 스텝(모듈)마다 실제 조건·결과·사진을 기록하고,
런시트를 고친 것도 모두 **변경 이력**에 남습니다. **로그인(이름 + PIN)** 이 있어 런은 만든 사람만 보고 고치며, 완료 후 **아카이브에 올리기로 동의한 런만** 모두에게 공개됩니다.

[DSIL Lab Portal](https://github.com/mhparkunist-del/dsil-portal) 과 같은 구조: 빌드 없는 정적 HTML/JS, **[Tabler](https://tabler.io/)** (MIT) + KAIST 블루, **[Pretendard](https://github.com/orioncactus/pretendard)** (OFL), PPT 출력은 **[PptxGenJS](https://gitbrent.github.io/PptxGenJS/)** (MIT).

배포 주소: **<https://mhparkunist-del.github.io/dsil-logsheet/>**

| 페이지 | 경로 | 요약 |
|------|------|------|

| 이력 | `history/` | 내 런 / 아카이브 / 전체(관리자) 범위의 기록·시트 수정을 팀·이름·공정 일자·런·동작별로 묶어 열람, CSV |

## 개념

```text
계정 (Account)        이름 + PIN. 팀 소속. 관리자 계정(관리자 / 0000)은 모든 런·계정을 봄
분류 (Domain)         반도체 소자 공정 | 패키징 공정   (모듈·흐름·런 모두 한 분류에 속함)

모듈 (Module)         예: PMMA 스핀코팅, EBL, 현상, 전자빔 금속 증착, 리프트오프, ALD, 전기 측정 / 다이싱, 다이 어태치, 와이어 본딩, 몰딩 …
  └ 조건 항목: 온도(°C), 시간(min), 레지스트(선택), 도즈(µC/cm²), … + 기본값 + 확인 사항. 세부 분류(세정·리소·증착·…)가 행의 대분류 기본값
  └ 기본 제공(seed) 모듈은 잠금 → 복사해서 내 모듈로

흐름 (Flow)           런시트 템플릿 = 행 × 열 시트. 단위 라벨(기판/웨이퍼/샘플/칩 …)·기본 수량.
  행 (Row)            큰 스텝. 번호 + 대분류(Cleaning, 리소그래피 …) + 이름 + 메모. 분기 구간에서도 행은 모든 분기에 걸쳐 맞춰짐
  셀 (Cell)           행 × (공통 또는 분기) 칸에 들어가는 모듈 + 계획 조건. 칸을 비우면 그 분기는 그 행을 건너뜀(skip)
  분기점 (Split)      행 범위(시작 행 ~ 끝 행)에 걸쳐 수량을 나눔. 예: 기판 4 → A(2): Cr/Au | B(2): Ti/Au. 끝 행 다음부터 다시 합침(merge). 분기 안에 또 분기 가능

런 (Run)              빈 런시트(기본) 또는 흐름 복사. 팀·이름은 계정에서, 단위·수량은 런마다.
  ├ 런시트 편집: 라이브러리 모듈을 행으로 추가(분기 구간이면 모든 분기에 같은 셀), 흐름 통째로 복사(분기점 포함, 빈 런이면 수량을 흐름에 맞춤),
  │             행 순서·대분류·이름, 분기별 셀 채우기/비우기/계획 조건, 분기점 범위·이름·수량
  ├ 스텝 로그: 완료(계획값으로 즉시) 또는 기록 창(작업자·팀·공정 일자·실제 조건·결과·특이사항·사진·상태)
  ├ 권한: 만든 사람만 보고 고침. 완료 시 "아카이브에 올릴까요?" 동의 → 모두 공개(읽기 전용). 내리면 다시 나만.
  └ 변경 이력: 누가(팀)·언제·무엇을. 추가만.
```

### 분기(split)와 행 맞춤

분기 구간에서도 **행(큰 스텝)은 하나의 축**입니다. 예를 들어 5행 "접촉 금속 증착"이 A·B 두 분기로 나뉘면 A 칸에는 Cr/Au 증착, B 칸에는 Ti/Au 증착이
들어가고, 9행 "접촉 후 O2 플라즈마"를 B 만 한다면 A 칸은 비워 **건너뜀**으로 둡니다. 그래서 분기가 있어도 모든 분기가 같은 행에서 끝나고, 인쇄·PPT 도
행·열이 맞습니다. 분기점의 끝 행 다음 행부터는 다시 공통(merge) 행이며, 분기 안에서 다시 분기점을 둘 수도 있습니다(상위 분기 범위 안).

## 사용 순서

1. **로그인**: 이름 + PIN. 처음이면 회원가입(이름·팀·PIN). 기본 계정(이현진 등, PIN 0000)은 첫 로그인 때 팀을 묻습니다.
2. **새 런 시작**(홈): 제목·시료 → 분류 → 시작 방법(**빈 런시트** 또는 **라이브러리 흐름 복사**, 분기 이름·수량 조정 가능) → 단위·수량 → 목표. 빈 런시트면 바로 편집 모드로 열립니다.
3. **런시트 구성**: 편집 모드의 **라이브러리에서 추가**에서 모듈을 골라 행으로 추가하거나 흐름을 통째로 복사합니다. 행의 ⑃ 버튼으로 그 행부터 분기점을 만들고, 분기마다 셀을 고치거나 비워서 건너뛰게 합니다.
4. **기록**: 스텝 **완료**(계획값 그대로 오늘·내 이름) 또는 **기록…**(실제 조건·결과·사진·건너뜀·실패).
5. **완료 → 아카이브**: 런 완료 처리 후 "아카이브에 올릴까요?"에 동의하면 모든 구성원이 볼 수 있습니다(읽기 전용). 다른 사람은 아카이브 런을 복제해 내 런으로 만들거나 내 흐름으로 저장할 수 있습니다.
6. **인쇄 · PPT**: 계획(런시트) / 실제 기록을 A4 가로로 인쇄하거나 PPT 한 장(16:9, 첫 열 = Step)으로 내려받습니다.
7. **이력**: 내 런 / 아카이브 범위에서 팀·이름·공정 일자별로 묶어 봅니다.

## 저장 방식

`assets/js/config.js` 의 `backend` 로 고릅니다.

- **`local`** (기본) — 브라우저 `localStorage`(사진은 IndexedDB). 계정·런·라이브러리가 **그 브라우저에만** 있습니다. 옛 형식(v2, 트리 모델) 데이터는 처음 열 때 행 × 분기 시트로 자동 변환됩니다.
- **`supabase`** — 연구실 전체가 같은 계정·라이브러리·런·아카이브를 봅니다. `supabase/schema.sql` 을 실행하고 URL·anon key 를 넣으세요. 계정 PIN 은 해시로 저장되지만 권한 검사는 브라우저에서 하므로 **내부용**입니다. 사진은 Storage 버킷 `run-photos`(public).

`config.js` 에서 분류(`domains`), 세부 분류(`categories`), 팀 목록(`teams`), 단위 라벨(`unitLabels`), 기본 계정(`defaultAccounts`), 회원가입 허용(`allowSignup`), PPT 글꼴(`pptx`)을 바꿀 수 있습니다.

```text
assets/js/config.js       설정
assets/data/library.js    기본 제공 라이브러리 (소자·패키징 모듈, 행 × 분기 흐름, 스플릿 예시) — 잠금
assets/js/sheet.js        시트 모델: 행·분기점·잎(열 분할) 계산, 검증, 레이아웃, 행/셀/분기 연산, 흐름 이어 붙이기, v2 트리 변환

assets/js/params.js       조건 항목 입력·요약·차이 표시, 조건 항목 정의 편집기
assets/js/pptx.js         PPT 한 장 출력 (PptxGenJS, 첫 열 = Step)
assets/js/home.js, run.js, history.js, library.js   화면
assets/js/ui.js           공통 UI 헬퍼
assets/css/portal.css     Tabler 오버라이드 + 시트 표·인쇄 스타일
supabase/schema.sql       공용 DB 스키마
```

## 저장소 보호
