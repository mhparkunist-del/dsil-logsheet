# DSIL Log Sheet

KAIST Device-to-System Integration Lab (DSIL) 의 **장비 사용 로그시트**입니다. 장비 옆에 두던 종이 로그시트를
그대로 옮긴 것으로, 쓰기 전에 **사용 시작**, 끝나면 **사용 종료**를 눌러 시각·시료·공정 조건·장비 상태를 남기고,
장비별 로그시트를 조회·검색·CSV·A4 인쇄합니다.

[DSIL Lab Portal](https://github.com/mhparkunist-del/dsil-portal) 과 같은 구조입니다: 빌드 없는 정적 HTML/JS,
디자인은 **[Tabler](https://tabler.io/)** (MIT) 위에 KAIST 블루, 한글 본문은 **[Pretendard](https://github.com/orioncactus/pretendard)** (OFL).

배포 주소: **<https://mhparkunist-del.github.io/dsil-logsheet/>**

| 페이지 | 경로 | 요약 |
|------|------|------|
| 홈 · 장비 현황 | `index.html` | 이름 + PIN 로그인. 장비 카드마다 `사용 가능 / 사용 중(누가·언제부터) / 이상 보고` 상태와 **사용 시작 · 사용 종료** 버튼, 최근 기록. 관리자는 가입 승인·계정·보안 이벤트 |
| 로그시트 | `sheet/` | **로그시트**(장비·기간·사용자·검색 필터, 통계, CSV, 인쇄용 보기) / **기록 작성**(사용 시작, 지난 기록 직접 입력) / **내 기록**(수정 기한 표시) / **관리자**(장비·조건 항목 관리, 이상 보고 점검 완료, 변경 이력, 데이터 백업) |

## 흐름

1. **사용 시작** — 장비, 시작 시각(기본 지금), 시료/소자 ID, 목적·내용. 조건 항목은 여기서 적어도 되고 종료할 때 채워도 됩니다.
   같은 장비에 다른 사람의 사용 중 기록이 있으면 시작할 수 없습니다(장비 설정에서 *동시 사용 허용* 가능).
2. **사용 종료** — 종료 시각, 공정·측정 조건, **장비 상태(정상 / 이상 있음)**, 비고. 이상을 남기면 장비 카드에 빨간 이상 보고가 뜨고
   **담당자 또는 관리자가 점검 완료**를 누를 때까지 유지됩니다(조치 내용은 변경 이력에 남음).
3. **지난 사용 기록 입력** — 시작 버튼을 놓쳤거나 종이 시트를 옮겨 적을 때 시작·종료를 한 번에 입력.
4. **수정·삭제** — 본인 기록은 작성 후 `editWindowDays`(7일) 안에만 수정, 그 뒤엔 관리자만. 삭제는 관리자만(사유 필수)이며
   **소프트 삭제**로 "삭제 포함" 조회와 변경 이력에 남습니다. 본인은 사용 중 기록만 "시작 취소"할 수 있습니다.
5. **인쇄용 보기** — 장비별 A4 가로 로그시트(장비·모델·위치·담당자·기간 표, 조건 항목이 열로, 서명 칸, 손으로 이어 쓸 빈 줄 5개).

시각 검증: 시작·종료가 현재보다 5분 이상 미래이거나, 종료가 시작보다 빠르거나, 1건이 48시간을 넘으면 거부됩니다(`config.logsheet`).

## 장비와 조건 항목

관리자 탭에서 장비를 추가하며 **이름·모델·위치·담당자·색·사용 규칙·동시 사용 허용**을 정하고, 로그시트의 **공정·측정 조건 항목**을
장비마다 다르게 둡니다(텍스트 / 숫자 / 선택 / 긴 글, 단위, 선택지, 필수 여부). `config.js` 의 `fieldTemplates` 에 있는 템플릿을 적용한 뒤 고쳐 쓸 수 있습니다:

| 템플릿 | 항목 |
|---|---|
| 프로브 스테이션 · 전기 측정 | 측정 항목(I-V / C-V / Transfer / Output / Pulse), 척 온도(°C), 프로브/카드 |
| 퍼니스 · CVD | 온도(°C), 가스, 유량(sccm), 압력(Torr), 공정 시간(min) |
| 스퍼터 · 이베퍼레이터 · ALD | 타겟/소스, 파워(W), 압력(mTorr), 공정 시간(min), 두께(nm) |
| RIE · 플라즈마 | 가스/유량, 파워(W), 압력(mTorr), 공정 시간(s) |
| 스핀코터 · 핫플레이트 | 물질/레지스트, 회전 속도(rpm), 시간(s), 베이크 |
| 현미경 · 분석 장비 | 모드, 배율/조건, 저장 파일/폴더 |

항목의 저장 키는 유지되므로 이름을 바꿔도 지난 기록과 연결됩니다. 기록이 있는 장비는 삭제 대신 비활성화됩니다.

## 로그인과 계정

- 첫 화면은 **이름 + PIN 로그인**입니다. 로그인하지 않고 로그시트 페이지를 열면 홈으로 돌아옵니다.
- **회원가입 신청** → 관리자가 홈의 가입 신청 목록에서 승인해야 로그인할 수 있습니다.
- **슈퍼계정** `관리자 / 0000` 과 `config.defaultAccounts` 의 기본 구성원(PIN `0000`)이 처음부터 있습니다. 각자 로그인 후 PIN 을 바꾸세요.
- 관리자 탭은 관리자 권한 계정에만 보이고, 들어갈 때 관리자 PIN(`adminPin`, 기본 `0000`)을 한 번 더 묻습니다(`adminUnlockMinutes` 동안 유지).
- 로그인 5회 연속 실패 시 10분 잠금, 페이지가 뜬 뒤 1.2초 안의 제출은 매크로 의심으로 기록됩니다(`config.security`, 웹훅 알림 선택).

## 저장 방식

`assets/js/config.js` 의 `backend` 로 고릅니다.

- **`local`** (기본) — 브라우저 `localStorage`. 설치 없이 바로 동작하지만 기록이 **그 브라우저에만** 남습니다. 관리자 탭 → 데이터에서 JSON 내보내기/가져오기.
- **`supabase`** — 연구실 전체가 같은 로그시트를 봅니다. `supabase/schema.sql` 을 Supabase SQL Editor 에서 실행하고 URL·anon key 를 넣으세요.
  이메일 magic link 로 로그인하며 처음 로그인한 계정은 승인 대기가 됩니다. 사용 중 중복 검사, 이상 보고, 변경 이력, 7일 수정 기한은 DB 트리거·RLS 가 강제합니다.

## 파일

```
index.html              홈(로그인·장비 현황)
sheet/index.html        로그시트 페이지
assets/js/config.js     설정(백엔드, 기본 계정·장비, 조건 항목 템플릿, 규칙)
assets/js/store.js      데이터 계층 (local / supabase 어댑터, 검증 규칙)
assets/js/forms.js      사용 시작·종료·기록 입력 대화상자
assets/js/portal.js     홈 화면
assets/js/sheet.js      로그시트 화면(조회·인쇄·CSV·관리자)
assets/js/ui.js         공통 UI 헬퍼(Tabler 모달, 토스트, 날짜)
assets/css/portal.css   Tabler 오버라이드 + 인쇄용 로그시트 스타일
supabase/schema.sql     공용 DB 스키마
```
