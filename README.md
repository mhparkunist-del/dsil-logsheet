# DSIL Run Sheet

KAIST Device-to-System Integration Lab (DSIL) 의 **공정 런시트**입니다. 반도체·2D 소자 공정을
**모듈**(한 번 정의해 재사용하는 공정 단위) → **흐름**(모듈과 다른 흐름을 재조합한 런시트 템플릿) → **런**(실제 시료에 대한 실행)
으로 체계화하고, 런의 **스텝(모듈)마다 실제 조건·결과·사진을 기록**합니다. 런 중에 런시트를 고치는 것(스텝 추가·삭제·순서·계획 조건)도
모두 **변경 이력**에 남습니다. 로그인은 없고, 브라우저에 기억한 "내 이름"이 모든 기록의 작업자로 붙습니다.

[DSIL Lab Portal](https://github.com/mhparkunist-del/dsil-portal) 과 같은 구조: 빌드 없는 정적 HTML/JS, **[Tabler](https://tabler.io/)** (MIT) + KAIST 블루, **[Pretendard](https://github.com/orioncactus/pretendard)** (OFL).

배포 주소: **<https://mhparkunist-del.github.io/dsil-logsheet/>**

| 페이지 | 경로 | 요약 |
|------|------|------|
| 홈 | `index.html` | 진행 중인 런 카드(진행률·현재 스텝·마지막 활동), **새 런 시작**, 최근 완료 런, 최근 활동 |
| 공정 런 | `run/` | 런 목록 + **런시트**: 스텝 표(계획 조건 vs 실제 조건, 상태, 작업자·시각, 결과·특이사항), 스텝 기록 창, 시트 편집 모드, 변경 이력, 인쇄(A4 가로)·CSV, 복제·흐름으로 저장 |
| 라이브러리 | `library/` | **공정 모듈**(분류·장비·예상 시간·조건 항목·확인 사항) / **공정 흐름**(모듈·서브 흐름을 순서대로 구성, 항목별 계획 조건, 펼친 미리보기) |

## 개념

```text
모듈 (Module)         예: PMMA 스핀코팅, EBL, 현상, 전자빔 금속 증착, 리프트오프, ALD, 전기 측정 …
  └ 조건 항목: 온도(°C), 시간(min), 레지스트(선택), 도즈(µC/cm²), …  + 기본값 + 확인 사항

흐름 (Flow)           예: "EBL 패터닝" = PMMA 스핀코팅 → EBL → 현상
  └ 모듈 또는 다른 흐름을 순서대로.   예: "금속 전극 형성" = [EBL 패터닝] → 금속 증착 → 리프트오프
                                    예: "MoS2 백게이트 FET" = 세정 → 박리 → OM → 라만 → [금속 전극 형성] → 어닐링 → 전기 측정

런 (Run)              흐름을 골라 시작. 서브 흐름은 펼쳐져 스텝이 되고(그룹 표시), 각 스텝은 모듈의 조건 항목과
                      계획값을 스냅샷으로 가짐 → 이후 모듈을 고쳐도 진행 중인 런은 바뀌지 않음
  └ 스텝 로그: 작업자, 시작·종료, 실제 조건(계획과 다르면 강조), 결과·관찰, 특이사항, 사진, 상태(완료/진행 중/건너뜀/실패)
  └ 시트 편집: 스텝 추가(모듈 1개 또는 흐름 통째로, 원하는 위치), 삭제(대기 스텝만), 순서, 계획 조건·이름·장비 수정, 되돌리기
  └ 변경 이력: 모든 작업 로그와 시트 수정이 누가·언제·무엇을 바꿨는지로 남음 (추가만, 삭제 없음)
```

## 흐름 (사용 순서)

1. **라이브러리 › 공정 모듈**: 연구실에서 쓰는 공정을 모듈로 정의합니다. 처음 열면 MoS2 소자 공정 예시 모듈 25개(세정, CVD 성장, 박리, PMMA 전사, OM/라만/AFM, PMMA·PR 스핀코팅, EBL, 포토 노광, 현상, 전자빔/열/스퍼터 증착, ALD, 리프트오프, RIE, 습식 식각, 어닐링, RTA, 프로브 측정, 패키징)이 들어 있습니다(`assets/data/library.js`, `config.seedLibrary`).
2. **라이브러리 › 공정 흐름**: 모듈을 순서대로 넣어 흐름을 만듭니다. 자주 반복되는 묶음(EBL 패터닝, 금속 전극 형성)은 별도 흐름으로 두고 다른 흐름에 **서브 흐름**으로 넣습니다. 항목마다 표시 이름·메모·계획 조건(모듈 기본값과 다른 값)을 줄 수 있고, 오른쪽에 펼친 런시트가 미리 보입니다.
3. **홈 › 새 런 시작**: 흐름, 제목, 시료/웨이퍼 ID, 담당자, 기판, 목표를 적으면 런 코드(`R-YYMMDD-NN`)와 런시트가 만들어집니다. 빈 런으로 시작해 스텝을 직접 넣을 수도 있습니다.
4. **런시트에서 스텝 기록**: 스텝의 ▶ 는 "지금 시작"(진행 중으로 표시), **기록** 은 기록 창을 엽니다. 실제 조건 칸에는 계획값이 채워져 있으니 다른 값만 고칩니다(계획과 다른 값은 표에서 노란색). 결과·특이사항·사진을 남기고 상태(완료/진행 중/건너뜀/실패)를 골라 저장합니다. 필수 항목이 비면 완료로 저장되지 않습니다.
5. **시트 편집**: 재작업·추가 공정이 필요하면 **시트 편집** 모드에서 원하는 위치에 스텝(모듈 1개 또는 흐름 전체)을 넣고, 순서를 바꾸고, 계획 조건을 고칩니다. 런 중 추가된 스텝은 보라색 배지가 붙습니다.
6. **런 마무리**: 모든 스텝이 끝나면 **런 완료 처리**. 더 보기에서 **복제**(이번 실제 조건을 다음 런의 계획으로), **흐름으로 저장**(이번에 실제로 진행한 순서·조건을 새 템플릿으로), 보류·중단·삭제.
7. **인쇄**: 런시트를 A4 가로로 출력합니다. **계획 양식**은 실제 조건·작업자·시각·확인란이 빈칸이라 클린룸에 들고 들어가 손으로 적을 수 있고, **실제 기록**은 채워진 값과 시트 변경 이력이 함께 나옵니다. CSV 로도 내보냅니다.

## 저장 방식

`assets/js/config.js` 의 `backend` 로 고릅니다.

- **`local`** (기본) — 브라우저 `localStorage`(사진은 IndexedDB). 설치 없이 바로 동작하지만 데이터가 **그 브라우저에만** 있습니다. 여러 사람이 한 런을 같이 쓰려면 아래 공용 DB 모드가 필요합니다.
- **`supabase`** — 연구실 전체가 같은 라이브러리·런을 봅니다. `supabase/schema.sql` 을 Supabase SQL Editor 에서 실행하고 URL·anon key 를 넣으세요. 로그인이 없으므로 **주소와 키를 아는 사람은 누구나 읽고 쓸 수 있습니다**(내부용). 사진은 Storage 버킷 `run-photos`(public) 에 저장됩니다.

## 파일

```text
index.html                홈
run/index.html            공정 런 (목록 · 런시트)
library/index.html        라이브러리 (모듈 · 흐름)
assets/js/config.js       설정 (백엔드, 분류, 런 코드, 사진 크기, 시드 여부)
assets/data/library.js    예시 라이브러리 (MoS2 소자 공정 모듈·흐름)
assets/js/store.js        데이터 계층: local / supabase 어댑터, 흐름 전개, 런·스텝·시트 변경 연산(순수 함수), 이력
assets/js/params.js       조건 항목 입력·요약·차이 표시, 조건 항목 정의 편집기
assets/js/home.js, run.js, library.js   화면
assets/js/ui.js           공통 UI 헬퍼 (Tabler 모달, 토스트, 날짜, data-show-if 토글)
assets/css/portal.css     Tabler 오버라이드 + 런시트 인쇄 스타일
supabase/schema.sql       공용 DB 스키마
```

이 저장소의 첫 버전(장비 사용 로그시트)은 커밋 `aa923c1` 에 남아 있습니다. 장비 예약·사용 로그는 [Lab Portal](https://mhparkunist-del.github.io/dsil-portal/equipment/) 의 장비 예약 모듈이 담당합니다.
