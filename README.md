# DSIL Run Sheet

KAIST Device-to-System Integration Lab (DSIL) 의 **공정 런시트**입니다. 반도체 소자 · 패키징 공정을
**모듈**(재사용 공정 단위) → **흐름**(모듈·서브 흐름·**분기점**을 재조합한 런시트 템플릿) → **런**(팀·이름·기판 수량이 붙은 실행)
으로 체계화하고, 런의 **스텝(모듈)마다 실제 조건·결과·사진을 기록**합니다. 런 중에 런시트를 고치는 것(스텝·분기점 추가, 순서, 계획 조건)도
모두 **변경 이력**에 남고, 이력은 **팀 / 이름 / 공정 일자 / 런**별로 묶어 봅니다. 로그인은 없고, 브라우저에 기억한 "내 이름·팀"이 기록의 작업자로 붙습니다.

[DSIL Lab Portal](https://github.com/mhparkunist-del/dsil-portal) 과 같은 구조: 빌드 없는 정적 HTML/JS, **[Tabler](https://tabler.io/)** (MIT) + KAIST 블루, **[Pretendard](https://github.com/orioncactus/pretendard)** (OFL), PPT 출력은 **[PptxGenJS](https://gitbrent.github.io/PptxGenJS/)** (MIT).

배포 주소: **<https://mhparkunist-del.github.io/dsil-logsheet/>**

| 페이지 | 경로 | 요약 |
|------|------|------|
| 홈 | `index.html` | 분류·팀·이름·기간 필터, **팀별 진행 중인 런** 카드, **새 런 시작**(분류 → 흐름 → 팀·이름 → 기판 라벨·수량 → 분기 수량 배분), 완료 런, 최근 활동 |
| 공정 런 | `run/` | 런 목록(분류·상태·팀·담당자 필터, 팀별 묶기) + **런시트 = 스플릿 표**(열 = 기판, 행 = 공정, 분기 구간은 분기별로 나란히). 스텝 **완료**(계획대로 즉시) / **기록…**(실제 조건·결과·사진·건너뜀·실패). 시트 편집: 스텝 추가·삭제·순서·계획, **분기점 추가·수정·삭제**. 변경 이력, 인쇄(A4 가로), **PPT 한 장**, CSV, 복제, 흐름으로 저장 |

## 개념

```text
분류 (Domain)         반도체 소자 공정 | 패키징 공정   (모듈·흐름·런 모두 한 분류에 속함)

모듈 (Module)         예: PMMA 스핀코팅, EBL, 현상, 전자빔 금속 증착, 리프트오프, ALD, 전기 측정 / 다이싱, 다이 어태치, 와이어 본딩, 몰딩 …
  └ 조건 항목: 온도(°C), 시간(min), 레지스트(선택), 도즈(µC/cm²), …  + 기본값 + 확인 사항

흐름 (Flow)           예: "EBL 패터닝" = PMMA 스핀코팅 → EBL → 현상        (서브 흐름으로 다른 흐름에 들어감)
  ├ 기판 라벨·기본 수량: 기판 4 / 웨이퍼 2 / 칩 6 …
  └ 분기점 (Split)    수량을 나눠 분기마다 다른 흐름.  예: 기판 4 → A(2): Cr/Au 전극 | B(2): Ti/Au 전극
                      분기 안에 또 분기점(중첩) 가능: B(3) → B1(1) / B2(2).  분기점 뒤의 항목은 다시 합쳐진(merge) 공정.

런 (Run)              흐름을 골라 팀·이름·시료·기판 라벨·수량·분기 배분을 정하고 시작. 스텝은 모듈 조건·계획값의 스냅샷.
  ├ 런시트 = 스플릿 표: 열 = 기판 1 … N, 공통 스텝은 전체 열, 분기 스텝은 해당 분기의 열만 차지
  ├ 스텝 로그: 작업자·팀·공정 일자, 실제 조건(계획과 다르면 강조), 결과, 특이사항, 사진, 상태(완료/건너뜀/실패)
  ├ 시트 편집: 스텝 추가(모듈 1개 또는 흐름 통째로, 공통 구간이나 특정 분기의 원하는 위치), 삭제(대기만), 순서, 계획 수정,
  │            분기점 추가(수량 배분) · 분기 이름·수량 수정 · 분기점 삭제(비어 있을 때)
  └ 변경 이력: 누가(팀)·언제·무엇을 — 추가만, 삭제 없음
```

## 사용 순서

1. **라이브러리**: 분류를 고르고 모듈·흐름을 만듭니다. 처음에는 예시 라이브러리(소자 모듈 24 + 패키징 모듈 9, 흐름 9)가 들어 있습니다. 흐름 편집기에서 **분기점** 버튼으로 분기를 만들고, 분기마다 모듈·흐름을 넣고, 분기점 뒤에 합쳐진 공정을 이어 넣습니다. 오른쪽 미리보기에 스플릿 표가 바로 그려지고 분기 수량 합이 맞지 않으면 경고합니다. 예시: `MoS2 BG-FET 접촉 금속 · 어닐링 스플릿`(기판 4 → Cr/Au 2 : Ti/Au 2 → 합침 → 200 °C 1 : 300 °C 3).
2. **새 런 시작**(홈): 팀·이름(필수) → 분류 → 흐름 → 기판 라벨·수량 → 분기 이름·수량 조정 → 제목·시료·목표. 런 코드 `R-YYMMDD-NN`.
3. **런시트에서 기록**: 스텝의 **완료**는 계획값 그대로 오늘 날짜·내 이름으로 즉시 완료. **기록…**은 실제 조건·결과·사진·상태를 입력. 필수 조건이 비어 있으면 기록 창이 열립니다.
4. **시트 편집**: 재작업·추가 공정·조건 스플릿이 필요하면 편집 모드에서 스텝·분기점을 넣고 이력에 남깁니다.
5. **인쇄 · PPT**: 계획(런시트) 또는 실제 기록을 A4 가로로 인쇄하거나 **PPT 한 장(16:9)** 으로 내려받습니다. 열 = 기판, 행 = 공정으로 정렬된 표라 회의 자료에 그대로 붙일 수 있습니다.
6. **이력**: 팀·이름·공정 일자별로 누가 무엇을 했는지 한눈에 봅니다.

## 저장 방식

`assets/js/config.js` 의 `backend` 로 고릅니다.

- **`local`** (기본) — 브라우저 `localStorage`(사진은 IndexedDB). 설치 없이 바로 동작하지만 데이터가 **그 브라우저에만** 있습니다.
- **`supabase`** — 연구실 전체가 같은 라이브러리·런·이력을 봅니다. `supabase/schema.sql` 을 Supabase SQL Editor 에서 실행하고 URL·anon key 를 넣으세요. 로그인이 없으므로 **주소와 키를 아는 사람은 누구나 읽고 쓸 수 있습니다**(내부용). 사진은 Storage 버킷 `run-photos`(public).

`config.js` 에서 분류(`domains`), 세부 분류(`categories`), 팀 제안 목록(`teams`), 기판 라벨 제안(`unitLabels`), PPT 글꼴·크기(`pptx`)를 바꿀 수 있습니다.

## 파일

```text
index.html                홈
run/index.html            공정 런 (목록 · 런시트)
history/index.html        이력
library/index.html        라이브러리 (모듈 · 흐름)
assets/js/config.js       설정
assets/data/library.js    예시 라이브러리 (소자·패키징 모듈, 흐름, 스플릿 예시)
assets/js/store.js        데이터 계층: local / supabase 어댑터, 흐름 전개(서브 흐름·분기점), 런·스텝·시트·분기 변경 연산, 이력
assets/js/layout.js       스플릿 표 레이아웃 (열 = 기판, 행 = 공정, 분기 재귀)
assets/js/params.js       조건 항목 입력·요약·차이 표시, 조건 항목 정의 편집기
assets/js/pptx.js         PPT 한 장 출력 (PptxGenJS)
assets/js/home.js, run.js, history.js, library.js   화면
assets/js/ui.js           공통 UI 헬퍼 (Tabler 모달, 토스트, 날짜, data-show-if 토글)
assets/css/portal.css     Tabler 오버라이드 + 스플릿 표·인쇄 스타일
supabase/schema.sql       공용 DB 스키마
```
